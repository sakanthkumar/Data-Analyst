# Workspace Rules & Constraints

## UI/UX Redesign Workflow

Whenever a screenshot of a page is provided for redesign:
1.  **Do NOT immediately redesign the page.**
2.  **First, perform a professional UX and Product Design Review** for every screen. Identify:
    *   Usability problems.
    *   Visual hierarchy issues.
    *   Unnecessary components.
    *   Spacing inconsistencies.
    *   Typography problems.
    *   Color misuse.
    *   Workflow problems.
    *   Explain why each issue hurts the user experience.
    *   Explain how enterprise products solve the same problem.
3.  **Explain the design reasoning** for the proposed changes before generating the layout.
4.  **Generate the high-fidelity UI** using Stitch MCP.
5.  **Redesign one page at a time** (do not redesign the entire application at once).
6.  **Ensure every redesign improves the previous version** instead of replacing it completely, maintaining strict consistency with the existing design system.

## Design Philosophy & Identity
*   **Aesthetic**: Minimal, Enterprise, Executive, Data-first, AI-first, Professional.
*   **Visual Elements**: Consistent spacing (8px grid), clean typography, generous whitespace, strong visual hierarchy, professional iconography, and modern data visualization.
*   **Tone**: Avoid educational, colorful, or playful dashboard styling. Make it feel like an enterprise SaaS application (e.g. Databricks, Stripe, OpenAI).
